# Content standards

- Source code and configuration are authoritative; README statements are claims to verify.
- Distinguish implemented behavior, documented claims, proposed extensions, external services and simulation. Unknown runtime facts remain explicitly unknown.
- Do not invent application/catalogue IDs, test results, deployments, APIs or references.
- Every module has at least one substantive implementation-code anchor; test, configuration, and documentation modules also trace to related implementation code. Lesson excerpts are bounded, so consult full source context.
- Module counts follow the number of implementation, test, configuration, and documentation paths: there is a minimum of six, and larger repositories receive more code-focused modules.
- Structural validation checks shape and referential integrity only; it does not establish correctness, pedagogy, functionality or security.
- Never publish credentials or sensitive sample data.
- Question answer keys are instructor-facing and live outside student assessments.

Packages use content schema 1.0.0; every module includes two lessons, a source-tracing exercise, and ten multiple-choice items.
