# Content standards

- Source code is the implementation of record; README claims are compared against named files and cited in each package.
- Every module starts with plain-language explanation and progresses to actual source code, tests, and operations.
- Lessons are standalone and include objective, prerequisites, progressive explanation, exact source excerpt, steps, expected behavior/limits, exercise, debugging, security, checks, and references.
- Every module has one substantive source-reading/implementation/debugging/safe-operations exercise and exactly ten MCQs (3 basic, 5 intermediate, 2 advanced), four options each.
- Answer keys are separate; each option has an explanation and the correct answer cites source.
- Final projects require functional implementation, tests, integration, demo evidence, acceptance criteria, rubric, and mentor guide.
- Never invent application/catalogue IDs, providers, test results, deployment outcomes, or implemented capabilities.
- Structural validation does not establish educational accuracy or prove code, services, APIs, infrastructure, or deployment work.
- Portable package paths are relative; source links point to the adjacent copied app tree.
