Active checks only after you say you are authorised.

A ZAP-style scanner that spiders a target you supply, checks every response passively, sends active probes only after explicit authorisation, and exports the alerts as HTML or JSON.

What it does

The capabilities

Every panel below is served by the console's real API — nothing here is a mock-up.

⌕

A same-origin spider

Breadth-first crawling discovers href and src links and GET form targets.

◈

Passive analysis

Missing CSP, frame and content-type headers, cookie flags, banner disclosure and mixed content are reported.

⚿

A hard authorisation gate

Reflected XSS, error-based SQL injection and traversal probes are disabled without an explicit confirmation.

▤

A real alert model

Risk, confidence, URL, parameter, evidence, description and remediation, de-duplicated and filterable.

◫

A Swing UI and a CLI

The same core runs interactively or headless for scripted assessments.

⇩

HTML and JSON export

The report can be exported for a ticket or an assessment record.

Architecture

How it works

The scanner core is independent of the UI: a spider produces a site tree, the passive analyser inspects every response, and the active analyser runs only when the authorisation flag is set. Alerts are stored in a de-duplicating in-memory store. The Swing UI and the headless CLI are two front ends over the same core, and the JUnit suite pins the analyser behaviour.
