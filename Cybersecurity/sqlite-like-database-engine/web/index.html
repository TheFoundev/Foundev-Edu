Put, get, delete — and survive a restart.

A step-by-step C implementation of a SQLite-like store: a sorted key array with binary-search lookup, insert, overwrite, delete, scan and length-prefixed binary persistence.

This is a C library and CLI, not a hosted product. It is part of the Foundev portfolio: a self-contained repository with its own tests and README. The page you are reading is a project console — the numbers below are computed from the repository, and the demo runs the project's own command.

The capabilities

Every panel below is served by the console's real API — nothing here is a mock-up.

Binary-search lookup

Keys are kept sorted, so a lookup is logarithmic rather than a scan.

⇄

The full write path

Insert, overwrite, delete and ordered scan are all implemented.

▤

A binary file format

Records are length-prefixed, written on save and read back on open.

◫

A command shell

The CLI exposes put, get and delete for hands-on use.

✓

Persistence tested

The suite writes a file, reopens it and checks the contents survive.

Architecture

How it works

src/ holds the table, the binary codec and the shell. The index is a sorted array rather than a full B-tree; the README says so plainly, because the point is the workflow and the file format, not a production storage engine. Saving walks the array and writes each record with its length; loading reads until the file ends.
