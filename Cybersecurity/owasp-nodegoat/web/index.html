Learn server-side security by breaking it.

A deliberately insecure Node.js application for practising OWASP-style attacks: weak credentials, a forgeable role cookie, a simulated injection flaw and unescaped output.

Open the console How it works
This is a deliberately vulnerable lab app, not a hosted product. It is part of the Foundev portfolio: a self-contained repository with its own tests and README. The page you are reading is a project console — the numbers below are computed from the repository, and the demo runs the project's own command.
What it does

The capabilities

Every panel below is served by the console's real API — nothing here is a mock-up.

⚿

Weak defaults

Default credentials and a role cookie the client can forge.

⌕

A simulated injection

The search endpoint keeps an injection-shaped flaw for guided practice.

◈

Reflected and stored XSS

Input is deliberately not escaped so the output paths can be studied.

⇄

Broken access control

User and admin endpoints demonstrate missing authorisation checks.

▤

Runs without a database

Only node:http and in-memory arrays are used, so the lab starts with npm start.

⚠

Not deployable

Every flaw is intentional; the README states the authorised-use boundary.

Architecture

How it works

src/app.js holds the intentionally vulnerable routes and the in-memory data. The test suite pins the expected (insecure) behaviour so a learner can see what changes when a fix is applied. The CSV stack names Express and MongoDB; this build uses the standard library and in-memory arrays so it runs with no services, while preserving the same attack surface.
