The headers, end to end, without a kernel.

A small userspace TCP/IP stack for learning how the protocols fit together: Ethernet, IPv4 and TCP header parsing with length checks, internet checksums, a packet builder and a loopback stack that maps ports to handlers.

Open the console How it works
This is a C library, not a hosted product. It is part of the Foundev portfolio: a self-contained repository with its own tests and README. The page you are reading is a project console — the numbers below are computed from the repository, and the demo runs the project's own command.
What it does

The capabilities

Every panel below is served by the console's real API — nothing here is a mock-up.

▤

Header parsing

Ethernet, IPv4 and TCP headers are decoded with explicit length checks.

✓

Internet checksums

The one's-complement checksum is computed and verified.

⌗

Packet building

IPv4 and TCP packets are assembled byte by byte.

⇄

A loopback stack

Ports map to handlers, so a request can be delivered without a TUN device.

◫

Raw buffers

The whole stack works on byte buffers, which makes every field visible.

Architecture

How it works

src/ contains the header codecs, the checksum, the builder and the loopback dispatcher. The CSV stack names a TUN/TAP device; opening one needs privileges and platform-specific code, so this build documents that path and tests the same packet logic over an in-process loopback instead.
