Built to be broken, in an authorised lab.

A deliberately vulnerable REST API for practising the OWASP API Top 10: object-level authorisation gaps, unverified tokens, mass assignment and seed data for the standard scenarios.

Open the console How it works
This is a deliberately vulnerable lab API, not a hosted product. It is part of the Foundev portfolio: a self-contained repository with its own tests and README. The page you are reading is a project console — the numbers below are computed from the repository, and the demo runs the project's own command.
What it does

The capabilities

Every panel below is served by the console's real API — nothing here is a mock-up.

◈

Insecure direct object references

User and vehicle resources can be read across accounts, exactly as the API Top 10 describes.

⚿

Unsigned tokens

Tokens are issued as unsigned JWTs and accepted without verification.

⇄

Mass assignment

The signup endpoint accepts fields the client was never meant to set.

▤

Seed scenarios

Seed data covers the practice flows so a fresh instance is immediately useful.

⚠

A lab only

The flaws are intentional and documented; this is training material, not a deployable service.

Architecture

How it works

A Spring Boot application with a small domain model and controllers for users and vehicles. The vulnerabilities are deliberate and isolated to the endpoints named in the README. The Maven build compiles the application and its JUnit tests. No JDK is installed in this environment, so the console reports the build honestly rather than pretending the service is live.
