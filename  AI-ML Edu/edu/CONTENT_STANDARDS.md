# Content standards

1. Teach source behavior, not the aspirational brief; label the difference clearly.
2. Begin every module with a beginner-friendly explanation, then trace the actual source symbol, its inputs, transformation, and output.
3. Cite source paths and include a short real code/config excerpt where available.
4. Include three progressive standalone lessons per module with exercises and source-based knowledge checks.
5. Create exactly ten MCQs per module, four options each, with a separate answer key and distractor explanations.
6. Cover data provenance, split/leakage risks, metrics, model/artifact availability, and deployment boundaries.
7. Include limitations and responsible-use safeguards for sensitive or consequential domains.
8. Run the structural validator; treat its output as evidence of structure/source-cue alignment, not proof of educational accuracy.
9. Keep these 36 packages separate from the previous 20-project AI/ML library.
